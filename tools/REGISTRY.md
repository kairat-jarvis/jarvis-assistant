# Реестр инструментов JARVIS

> Единая карта: какой инструмент где лежит, когда использовать, что читает/пишет.
> JARVIS обращается сюда ПЕРЕД тем, как делегировать задачу — чтобы выбрать нужный модуль, а не тянуть весь код в контекст.

## Принцип
- Каждый инструмент — **отдельный репозиторий** в `github.com/kairat-jarvis`.
- В этом репо (`jarvis-assistant`) только **карточки** (`tools/<name>/TOOL.md`) — не сам код.
- Ядро JARVIS (системный промпт, концепт, схема Supabase, n8n workflow'ы) — в корне.
- Подгружать карточку инструмента в контекст — только когда триггер сработал.

## Алгоритм выбора инструмента

1. **Услышал запрос** → ищи триггер в таблице выше.
2. **Нашёл совпадение** → открой `tools/<name>/TOOL.md`, прочитай правила и MCP-зависимости.
3. **Не нашёл совпадения** → работай стандартными MCP (Supabase, Drive, Calendar, Gmail).
4. **Несколько инструментов подходят** → выбери по основному домену, остальные — как вспомогательные.
5. **После выполнения** → логируй в `jarvis_agent_logs` с полем `tool=<имя инструмента>`.

## Как добавить новый инструмент

1. Создать репо `github.com/kairat-jarvis/<name>`.
2. Создать папку `tools/<name>/` в этом репо.
3. Написать `TOOL.md` по шаблону (см. любую существующую карточку):
   - Назначение, Репозиторий, MCP-серверы, Когда использовать, Интеграция с JARVIS, Правила, Статус.
4. Добавить строку в таблицу выше.
5. Закоммитить.

## Шаблон TOOL.md

```markdown
# <name>

## Назначение
<1-2 предложения: что делает>

## Репозиторий
`github.com/kairat-jarvis/<name>`

## MCP-серверы
- `<server>` — <для чего>

## Когда использовать
Триггеры: «…», «…», «…».

## Интеграция с JARVIS
- **Читает**: <таблицы/источники>
- **Пишет в**: `jarvis_memory` (type='<…>')
- **Логирует в**: `jarvis_agent_logs` (action='<…>')

## Правила
- <правило 1>
- <правило 2>

## Статус
🟢/🟡/🔴 <короткое описание>
```
