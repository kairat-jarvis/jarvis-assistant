# MVP: Expertise Archetypes — проверка гипотезы на 100-200 заключениях

## Цель MVP
Доказать за 2 недели и ~$50 API-бюджета, что:
1. Pareto-распределение действительно работает (~20% архетипов = ~80% замечаний) на узком срезе.
2. Архетипы устойчиво кластеризуются — одно и то же нарушение, сформулированное 20 разными экспертами, сходится в один кластер.
3. Автопривязка к пунктам НТД через embeddings даёт точность ≥ 80% на валидационной выборке.

Если хотя бы 2 из 3 гипотез подтверждаются — масштабируем на полный корпус.

## Скоуп MVP
- **Один тип объектов**: школы (общеобразовательные, новое строительство, II класс ответственности). Причина — их много, типовые, сопоставимые.
- **Один раздел ПСД**: АПС + СОУЭ (у Кайрата здесь глубочайшая экспертиза — возможна быстрая ручная валидация).
- **Один регион для начала**: Алматы (самый большой поток), потом Астана + Шымкент для проверки региональной воспроизводимости.
- **Период**: последние 12 месяцев.
- **Размер**: 150 заключений × ~15 замечаний по АПС/СОУЭ ≈ 2250 атомарных замечаний.

## Шаги

### Шаг 1. Инфраструктура (день 1)
```
Supabase: применить scripts/expertise_archetypes_schema.sql
├── expertise_reports
├── expertise_comments
└── comment_archetypes
```

### Шаг 2. Сбор корпуса (день 2-3)
- Выгрузить 150 заключений в PDF/DOCX (через доступ Кайрата к архиву филиала)
- Положить в `load/expertise_mvp/`
- Скрипт `scripts/ingest_expertise_reports.py`:
  - pdfplumber / python-docx → raw_text
  - извлечь метаданные (номер, дата, объект) регэкспами + Claude Haiku для неоднозначных случаев
  - UPSERT в `expertise_reports` по `source_hash`

### Шаг 3. Атомизация (день 4-5)
- Скрипт `scripts/atomize_comments.py`:
  - для каждого report с status='pending' → вырезать раздел «Замечания» (регэксп + Haiku как fallback)
  - вызвать `prompts/expertise_comment_atomizer.md` на Sonnet 4.6
  - вставить атомы в `expertise_comments` с status='atomized'
- Бюджет: 150 × ~$0.02 = ~$3

### Шаг 4. Embeddings (день 6)
- OpenAI text-embedding-3-small (1536 dim) для `normalized_text` каждого замечания
- Batch API: 2250 × $0.00002 = ~$0.05
- UPDATE `expertise_comments.embedding`

### Шаг 5. Классификация + первичные архетипы (день 7-9)
- Скрипт `scripts/classify_comments.py`:
  - Для каждого замечания: `match_comment_archetype()` → top-5 кандидатов (на первом прогоне архетипов ещё нет — все будут NEW_ARCHETYPE)
  - clause_vectors search → top-5 пунктов НТД
  - Вызов классификатора (Sonnet 4.6)
  - Если NEW_ARCHETYPE и уже есть ≥ 3 замечания с похожей формулировкой (через HDBSCAN на embeddings) — создать архетип
- Альтернатива: сначала чистая кластеризация (HDBSCAN или agglomerative clustering на embeddings), потом для каждого кластера Claude даёт `title` + `canonical_description`. Быстрее и дешевле.
- Бюджет: 2250 × ~$0.005 = ~$12

### Шаг 6. Валидация (день 10-11)
- Ручная проверка Кайратом: случайные 100 замечаний → правильно ли попали в архетип?
- Метрика: точность кластеризации ≥ 85%, точность привязки к НТД ≥ 80%
- Где ошибки — log в `metadata.validation_notes`, скорректировать пороги `match_threshold`

### Шаг 7. Аналитика (день 12-13)
- `v_pareto_analysis`: сколько % архетипов дают 80% замечаний?
- `v_top_archetypes_by_slice`: топ-20 для среза «школы / АПС»
- `v_archetype_regional_drift`: отличается ли топ для Алматы vs Астана?
- Сгенерировать Excel-чеклист «Топ-50 типовых замечаний по АПС/СОУЭ для проектировщиков школ»

### Шаг 8. Решение go/no-go (день 14)
- Если гипотезы подтверждены → план масштабирования: все разделы, все типы объектов, все филиалы, 3 года.
- Если нет → диагностика: проблема в данных, в промптах, или в модели?

## Критерии успеха MVP

| Метрика | Цель |
|---|---|
| Pareto: доля архетипов для 80% замечаний | ≤ 25% (гипотеза работает) |
| Точность автокластеризации (ручная валидация 100 шт.) | ≥ 85% |
| Точность автопривязки к НТД | ≥ 80% |
| Доля `needs_review` | ≤ 15% |
| Топ-20 архетипов по АПС — осмысленность по оценке Кайрата | 18+ из 20 адекватны |
| Региональный сдвиг | статистически значимый для ≥ 5 архетипов |

## Бюджет MVP
- Claude Sonnet 4.6 (атомизация + классификация): ~$15
- OpenAI embeddings: ~$0.05
- Supabase: в рамках существующего проекта
- Время Кайрата: ~40 часов (включая ручную валидацию)
- **Итого: ~$15-20, 2 недели календарных**

## Риски и митигации

| Риск | Митигация |
|---|---|
| PDF у разных филиалов отформатированы по-разному — парсер ломается | На MVP берём только Алматы (единый формат), потом добавляем нормализацию |
| Эксперты формулируют одно нарушение слишком по-разному → плохая кластеризация | Каноническая формулировка `normalized_text` + HDBSCAN на embeddings, а не точное совпадение |
| `clause_vectors` не покрывает все упомянутые НТД | Помечаем `ntd_code_unverified`, не блокируем пайплайн |
| Персональные данные в заключениях (ФИО, адреса) | Анонимизация на этапе ingest (regex + Haiku) |

## Что даст MVP для NIW
Даже на 150 заключениях получим:
- Работающий прототип с измеримым эффектом (ускорение экспертизы, снижение итераций с проектировщиком)
- Визуализации Pareto (сильный графический артефакт для письма)
- Первая версия методики для публикации в «Промышленное и гражданское строительство» или «Вестник КазГАСА»
