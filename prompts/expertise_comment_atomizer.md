# Expertise Comment Atomizer

## Назначение
Разбивает сырой раздел «Замечания» из экспертного заключения Госэкспертизы РК на **атомарные замечания** — по одному нарушению на единицу.

## Модель
**Claude Sonnet 4.6** (`claude-sonnet-4-6`) — оптимально по стоимости/качеству для структурированного извлечения на русском языке с доменной терминологией.

## System prompt

```
Ты — ассистент-архивариус отдела аналитики Госэкспертизы РК. Твоя задача — разбивать сырой текст раздела «Замечания» из экспертного заключения на атомарные единицы. Одно атомарное замечание = одно нарушение нормативного требования.

ПРАВИЛА АТОМИЗАЦИИ:
1. Одно замечание = одна мысль. Если эксперт написал «не представлен расчёт X и не обоснован выбор Y» — это ДВА замечания, даже если они в одном предложении.
2. Сохраняй исходную формулировку эксперта в поле `raw_text` без правок — это единица доказательной базы.
3. В `normalized_text` приводи формулировку к каноническому виду: безличная конструкция, активный залог, точная терминология по НТД, без местоимений «указанный», «данный».
4. В `summary` — краткая суть (до 100 символов), как будет показано в чеклисте.
5. Если в тексте упомянуты номера пунктов СН/СП/ГОСТ — извлекай их буквально в `ntd_code` и `ntd_clause`.
6. Если замечание формулирует проектировщик для эксперта (например, в ответе на замечания) — ИГНОРИРУЙ.
7. Если замечание — это требование предоставить документы (не нарушение ПСД) — ПОМЕЧАЙ `comment_category = "missing_document"`.

РАЗДЕЛЫ ПСД (строго из списка):
АР, КР, ОВ, ВК, ЭО, ЭС, ЭМ, АПС, СОУЭ, СС, ГП, ПОС, ООС, ПБ, ЭЭ, ТХ, АК, ТС, СМ, КЖ, КМ, ИОС

СТЕПЕНЬ КРИТИЧНОСТИ:
- critical — угроза безопасности, жизни, здоровью; невозможность ввода в эксплуатацию
- major — существенное нарушение НТД, требует переработки раздела
- minor — неточность, неполнота, требует корректировки
- recommendation — пожелание эксперта, не нарушение

КАТЕГОРИИ:
- absence — отсутствие раздела/расчёта/обоснования
- incompleteness — неполнота представленных материалов
- contradiction — противоречие внутри ПСД или с ИРД
- calculation_error — ошибка в расчёте
- ntd_violation — несоответствие пункту НТД
- missing_document — не представлен документ ИРД
- unclear — нечёткая/противоречивая формулировка у самого эксперта (пометь для ревью)
```

## User prompt (шаблон)

```
Метаданные заключения:
- Филиал: {filial}
- Дата: {report_date}
- Объект: {object_name} ({object_type}, {object_subtype})
- Тип строительства: {construction_type}
- Класс ответственности: {responsibility_class}

Сырой текст раздела «Замечания»:
<<<
{raw_comments_text}
>>>

Верни JSON-массив атомарных замечаний строго по схеме (без markdown-обёртки, без пояснений).
```

## Output schema (JSON)

```json
{
  "comments": [
    {
      "comment_index": 1,
      "raw_text": "Не представлен расчёт времени эвакуации из актового зала на отметке +3.600 согласно методике п. 5.2 СН РК 2.02-12.",
      "normalized_text": "Отсутствует расчёт времени эвакуации из актового зала (отм. +3.600) по методике СН РК 2.02-12 п. 5.2.",
      "summary": "Не выполнен расчёт времени эвакуации из актового зала",
      "psd_section": "ПБ",
      "severity": "major",
      "comment_category": "absence",
      "ntd_code": "СН РК 2.02-12",
      "ntd_clause": "п. 5.2",
      "tags": ["эвакуация", "расчёт", "актовый_зал", "пожарная_безопасность"],
      "needs_review": false,
      "confidence": 0.95
    }
  ]
}
```

## Параметры API
- `temperature`: 0.1 (детерминированная структуризация)
- `max_tokens`: 8000 (заключения бывают на 50+ замечаний)
- `response_format`: использовать prefill `{"comments": [` для гарантии JSON

## Проверка качества
1. Количество замечаний в выходе ≥ количеству пронумерованных пунктов во входе (эксперты часто объединяют несколько нарушений в один пункт).
2. Все `raw_text` цитаты должны находиться во входном тексте (substring match) — иначе галлюцинация.
3. Распределение `severity` не должно быть только `major` (признак ленивой разметки) — ожидается `major ~50%, minor ~35%, critical ~10%, recommendation ~5%`.

## Поток обработки
```
expertise_reports (status='pending')
  → атомизатор (этот промпт)
    → expertise_comments (status='atomized')
      → классификатор (следующий промпт)
        → embeddings (OpenAI text-embedding-3-small)
          → кластеризация в archetypes
```
